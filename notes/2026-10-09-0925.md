# 2026-10-09 09:25 ｜ Q5 / Q14a 拍板关闭（伺服时盖章）

## 决策

- **Q5 ✅**：采纳「一次性门票 token + 结构校验」。门票由伺服路由盖章进 HTML（`{{__TOKEN__}}`），每次加载新发；桥校验 `source` + token + `values` 结构；兜底为 Q8 用户确认。无需 URL query 或 init 消息。
- **Q14a ✅**：用户选「部署时替换（盖章）」，实现收敛为**伺服时盖章**——仓库存带占位符的干净源码，`webServer` 路由在响应时替换保留占位符（`__NAME__`/`__VERSION__`/`__TOKEN__`）后返回成品。

## 为什么不是字面上的「部署时写死」

1. 字面部署时替换会污染 git 工作树：每次部署产生「假变更」，`git diff` 噪声淹没真实修改；
2. 不同会话要不同初始值就得生成多份文件，与「部署指针 = 分支@提交」的版本模型冲突；
3. `__VERSION__` 鸡生蛋：值就是提交号，提交前无法知道；
4. token 若在部署时写死，就变成所有实例共享的长期票据，失去「一次性」语义。

伺服时盖章同时拿到两个好处：**webapp 零初始化代码**（用户要的「盖章」体验）+ **仓库零污染、token 按次发放、版本号正确**。副作用：直接双击磁盘上的源文件会看到未替换的占位符（可接受降级），经伺服 URL 访问永远是成品。
