# 2026-10-17 16:10 — DSH 0.2.1 兼容性校验 + 固化 compat 测试

## 背景

用户把 DeepSeek Harness 从 0.2.0 升级到 **0.2.1-rc.1**（desktop 壳 44.7.0，两者版本号独立），要求校验插件兼容性（不破坏对 0.2.0 的兼容），并把校验操作固化成测试、在 AGENT.md 声明。

## 关键发现

1. **分发形态变了**：`resources/app.asar` 从解包目录变成真归档，旧证据路径 `D:\DeepSeek Harness\resources\app.asar\dsh\` 不再可直接读。为此写了零依赖 asar 解析器 `scripts/asar.mjs`（两层 Chromium Pickle 嵌套：外层 u32 给 header pickle 尺寸，内层 pickle 里才是 JSON 字符串；首版实现少算一层，JSON 尾部混入二进制报错后修正）。
2. **新版 GUI 加了 web 鉴权**（"dsh web authentication required"），但插件自有前缀 `/dsh-web-app/api/*` 依旧零鉴权直达——Q1 结论在 0.2.1 仍成立。
3. **兼容性结论：全绿**。client 契约表面（7 个槽位、TurnTailOwnerProps、TurnLocation 对象形态、foldCompletedTurns、standardProps 的 useChat/sessionId、web shell 的 `__ModuleLoader__`）逐项 grep 通过；host 半身线上探针（/api/health 含 skills registered、/api/list、铸票→伺服全链路）通过；宿主四包 dsh-commands/dsh-tools/dsh-host-webserver/dsh-skill 均在，peerDepsMeta 无需改；55 项单测全过。无需任何代码改动，对 0.2.0 的兼容自然保持（契约表面两侧一致）。
4. 顺带发现：用户测试期间部署了第二个应用 decision-wheel；插件在 desktop profile 的装载是 junction（`profiles/desktop/node_modules/dsh-web-app`）。

## 交付物

- `test/compat.test.mjs`：12 项检查 = 9 静态（asar grep，按 `DSH_ASAR` 定位，找不到自动 skip）+ 3 线上（按 `DSH_GUI_URL` 启用）。npm 脚本 `test:compat`。
- `scripts/asar.mjs`：只读 asar 解析器（list/readText/readFile）。
- `AGENT.md` 新增「DSH 升级后的兼容性校验」节（流程：升级 → 跑 compat → 契约变了先改测试再改实现并同步 sdk-notes）。
- `docs/sdk-notes.md` 头部补版本基线说明（0.2.0 采集 / 0.2.1 起走 compat 测试复核）。

## 以后升级 DSH 时

```powershell
node --test test/compat.test.mjs                              # 静态层
$env:DSH_GUI_URL="http://127.0.0.1:<port>"; node --test test/compat.test.mjs   # 连线上层
```
